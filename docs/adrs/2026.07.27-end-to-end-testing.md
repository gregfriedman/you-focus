# ADR: End-to-end Testing

## Context and Problem Statement
End-to-end testing provides us our highest level of confidence that, when released, the software will do what we intended. Without it, we could have 100% unit test coverage and yet the software could still fail. 

We have been doing the end-to-end testing manually, but it has been causing some pain:
1. It is cumbersome to load the extension into the browser, navigate to multiple different pages, and confirm the correct items are hidden.
2. When we come back to the code later, we can't remember all the things we had previously manually tested.
3. We are operating against a 3rd party website. When there is a regression, we don't have any way to compare the latest version of the website against what we expected to be there.
4. Automated testing is difficult because it involves loading a browser extension
5. Automated testing is difficult because the 3rd party website's Terms of Service prohibits automating interactions with the website directly
6. Automated testing is difficult because the 3rd party website's Terms of Service prohibits downloading the content
7. The 3rd party website could introduce new elements, and we'd want to decide if they are distractions, but we don't have a way to capture our decision.

## Considered Options
- Playwright
- Cypress
- Selenium

## Decision Outcome
Decided to use Playwright because it supports loading a browser extension into Chrome. Instead of testing directly against the 3rd party website, we will use software tools to generate an ephemeral, sanitized fixture from a locally saved webpage that does not get checked into source control and which should be sufficiently altered so as not to violate Terms of Service. Also, it's a good opportunity to get familiar with Playwright as an alternative to Cypress which I have a lot of experience with.

Cypress may support loading a browser extension but by jumping through more hoops like it requires running Chrome for Testing. Also, Cypress does not support custom browser protocols so we can't use it to test extension UI via "chrome-extension://". 

Selenium might work but seems harder to configure and maybe had extension loading bugs reported. 

### Consequences
- Good, reduces the friction of running end-to-end tests
- Good, test code documents what we expect to be tested
- Good, golden master snapshots capture what we most recently approved as "not distracting"
- Bad, minor changes to the 3rd party website could result in frequent false negatives
